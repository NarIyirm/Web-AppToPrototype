# 01 产品范围与验收

2026-10-20范围更新：用户确认桌面整体可用，要求规划Expo移动端，采集网页及其他原生App；最新明确Android/iOS同等优先，覆盖下方历史“移动端优先Android”。完整方案见[25 移动端计划](25-mobile-web-and-native-plan.md)，尚未实施。网页结构重建与原生画面视觉推断分级，不承诺从任意第三方App恢复全部可编辑图层或业务逻辑。

版本：方案基线v1.0 / 2026-10-20 Windows首版0.1.0候选｜已完成支持范围内的首版开发，最终用户验收待完成；当前边界和证据见[发布检查](21-desktop-release-verification.md)，下方原需求/目标保留。

## 1. 使用背景

用户计划从事产品经理工作，习惯用 vibe coding 快速制作可运行 demo；工程团队希望最终保留可编辑、可演示的 Figma 原型用于归档和交接。用户已经使用过 html.to.design，希望自行开发一个接近其效果的工具，减少付费转换服务依赖。

用户已明确要求：独立桌面程序、内置浏览器、可选择转换范围、未来探索移动 App，移动端优先 Android。当前阶段先验证纯桌面产品及其 Figma 导入插件的可用性和稳定性。

## 2. 核心目标与分层

| 层次 | 需要实现的结果 | 不应混淆的概念 |
|---|---|---|
| L1 可编辑 | 文字可修改，图像可替换，基础形状可调整 | 整张截图放进 Frame 不是完整可编辑转换 |
| L2 可维护 | 层级清晰、语义命名、基础布局可调整 | 大量绝对定位虽然可编辑，也不自动成为设计系统 |
| L3 可演示 | 捕获的关键状态可跳转、弹窗可打开关闭 | 任意 JavaScript 业务逻辑不会自动成为 Figma 行为 |
| L4 可交接 | 源页面、选择范围、状态、降级区域与导入报告可追溯 | 外观接近不代表所有交互都已覆盖 |

本轮完成版包含 L1、基础 L2、有限 L3 和基础 L4。正式设计系统、组件库绑定与完整业务规则提取另行规划。

## 3. 范围与优先级

### P0：先形成可靠链路

- Windows 桌面程序与内置浏览器，可打开 localhost demo 和普通 HTTPS 页面。
- 手动登录目标网站；登录会话独立保存在应用分区，允许清除，不读取外部 Chrome 配置。
- 当前视口和单元素采集。
- 本地中间数据包；自建 Figma 插件可手动加载并创建基础图层。
- 文字、纯色、边框、圆角、常见图片、简单 SVG 的转换。
- 字体缺失、资源获取失败、不可转换区域明确报告。
- 可取消、失败后可重试，避免污染用户已有设计。

### P1：完整桌面验证版

- 有界整页采集、Section 点选、严格矩形裁剪、吸附完整元素、多选与排除。
- 图片裁切、基础渐变和阴影、常见表单外观、有限 Flex Auto Layout。
- 捕获历史、数据包重开、导入报告、视觉对照与问题定位。
- 桌面端与 Figma 本地桥接；受环境限制时保留文件导入。
- 手动保存多个状态、选择触发元素并连接跳转或 Overlay。
- Windows 可运行分发包与安装、使用、恢复说明。

### P2：后续扩展

Android 采集、桌面原生窗口、iOS、代码辅助、自动组件提取、库匹配、AI 重建、自动探索、增量双向同步、团队服务和云端存储。

## 4. 使用界面与任务流程

主工作区包含：地址与导航区、目标网页区、采集模式工具条、捕获列表、结果/告警侧栏、Figma 连接状态。

用户只需要理解“选什么、保留什么、导出到哪里”。DOM、CDP、IPC、schema 等实现名词放入诊断视图，不放在主要操作流程中。

### 4.1 第一次使用

1. 启动桌面程序，输入 demo 地址；需要登录时在目标网页正常登录。
2. 开启选择模式，选择当前视口或一个完整区块。
3. 在预览确认范围，看到原生重建、图片保留和缺失区域统计。
4. 保存捕获，输入名称；默认使用页面标题和区块内容生成建议名称。
5. 打开 Figma 桌面版，在可编辑文件运行自建导入插件。
6. 通过文件导入捕获；桥接完成后可以改为连接并发送。
7. 插件完成后定位新 Frame，显示结果和告警；桌面端保存对应报告。

### 4.2 日常局部采集

选择模式与正常浏览模式分离。选择时阻止一次选中动作意外触发导航；退出选择模式后恢复网页操作。Esc 取消当前选择，Enter 确认，Shift 多选，Alt+单击排除；这些是待实现的默认快捷键，必须可在 UI 按钮中完成相同操作。

选中区块后可“扩大到父级”“缩小到子级”“只保留可见区域”“保留完整内容”。框选须显示尺寸、当前视口宽度、是否跨滚动区域。长页选择支持滚动后保留已选对象；最终采集前重新校验对象是否仍然存在。

### 4.3 手动原型流程

1. 保存状态 A。
2. 正常操作网页，保存状态 B。
3. 回到捕获 A 的预览，点选可点击的导入元素或手动画热点。
4. 指定 B 是跳转目标还是 Overlay；指定关闭行为。
5. 导入全部状态后，插件按映射建立连线。

第一版不根据一次点击猜测业务因果。自动记录仅作为后续候选信息，用户确认的连接才进入原型。

## 5. 选择范围的产品规则

| 模式 | 用户意图 | 输出 |
|---|---|---|
| 视口 | 保留当前所见 | 一个裁剪到视口的 Frame |
| 整页 | 保留当前文档已展开内容 | 一个长 Frame；明确采集高度与终止原因 |
| 元素/Section | 保留有意义的完整区块 | 一个包含后代的 Frame，可保留区块背景 |
| 严格矩形 | 精确保留指定边界 | 选区外元素裁剪，内部仍按结构重建 |
| 元素吸附矩形 | 不切断卡片、文字或按钮 | 扩展到确认后的完整元素边界 |
| 多选 | 同时采集多个独立部分 | 默认每个选择一个 Frame；可选按原相对位置合并 |
| 排除 | 去掉悬浮按钮或无关内容 | 默认保留原空位，不重新排版原页面 |

“完整内容”针对已存在的文档与可访问子树；不包含还没加载的无限列表全部数据，也不意味着所有路由、Tab 和隐藏业务分支。

## 6. 项目级完成定义

- P0/P1 任务按阶段通过；M0 外部可行性已有实际证据。
- 支持范围内基准页面达到文档 05 的视觉与可编辑性目标。
- 不支持属性和图片降级不能静默忽略，报告必须可定位到捕获与节点。
- 至少一个用户实际 demo 的核心页面和一条状态流程通过人工检查。
- 同一数据包可重复导入，不会误删原设计；断线、取消和插件重开可恢复。
- 安装/运行文档与本机真实验证记录存在；没有完成的任务保持未完成状态。
- 进度、已知问题、下一步和对应版本全部落盘。

目标值是验收要求，不是已达成结果。现有对话没有提供可实测的 demo URL、Figma 文件或设备，后续必须补充真实验证材料。
