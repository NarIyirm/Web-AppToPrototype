# 05 验证、质量与稳定性

2026-10-20 BUG-002新增本地定向基线：滚动文字、实时文本、快照后的文档增长、真实缩放拒绝、旧结果保留及实际capture-send按钮。普通更新保留不可变场景并中止不匹配参考；导航/取消与真实视口保护继续。当前结果见PROGRESS末尾，不要求用户重做旧已接受全页矩阵。

版本：v1.1｜下列完整质量数字仍为初始目标；实际开发证据和已获用户确认的分批范围以PROGRESS、USER-TEST-RESULTS及各批验收说明为准，不将局部通过当作全矩阵完成。

## 1. 验证分层

| 层 | 验证对象 | 方法 | 必须避免的误判 |
|---|---|---|---|
| 契约 | 包格式、树、引用、预算 | 自动校验、正常与畸形样例 | JSON 能解析不等于可执行 |
| 算法 | 坐标、文本 runs、裁剪、样式 | 固定输入与几何断言 | 与实现一模一样的测试无法发现逻辑错误 |
| 浏览器 | 实际布局、懒加载、选择 | Electron 实际页面与交互 | 普通浏览器结果不代表嵌入视图正确 |
| 插件 | 字体、图片、图层、连线、撤销 | 实际 Figma 文件导入 | mock API 不证明 Figma 可用 |
| 端到端 | 捕获到导入及报告 | 同一 captureId 的源截图和 Figma 导出对照 | 不同状态/字体/DPR 图像不能直接比较 |
| 稳定性 | 重复、取消、断线、崩溃 | 故障注入和重复任务 | 进度 100% 不代表最终图层提交成功 |

初期测试集中在真实有风险的转换和恢复路径，不为按钮样式、静态文案编写镜像测试。Figma 自动化不可用时允许人工执行，但必须有步骤与证据，不得用测试替身冒充。

## 3. 质量指标与口径

### 3.1 可编辑性

- 基础集 F01/F02 中可见普通文字 100% 对应可编辑 TextNode，内容不丢失、不重复；不能把文字整体栅格化后计为通过。
- 原生覆盖率按叶子内容计数：native 原生文字/形状/矢量内容数 ÷ 所有有意义的叶子内容数。容器 Frame 和对照截图不参与分母，不允许通过增加空 Frame 提高覆盖率。
- 图片本来就是栅格资源，不要求变成矢量；它应当可替换。Canvas 等降级区域单独统计 rasterized，不混入普通图片。
- 复杂页面原生覆盖率先测基线，不做未经测量的“90% 还原”宣传；每份报告显示 native/approximated/rasterized/missing 数量。

### 3.2 几何与视觉

- 固定字体的基础 fixture：至少 95% 标注锚点的位置/尺寸误差 ≤2 CSS px；关键元素不允许缺失或重叠顺序错误。
- 纯色在 sRGB 通道归一化后比较；基础纯色目标每通道误差 ≤2/255，透明度混合单独看最终显示。
- 对照图统一 CSS 尺寸、背景、颜色空间、DPR=1 导出。必须使用同一次捕获的源状态，不能事后重新访问已变化网站充当原图。
- 可选 SSIM 初始参考值 ≥0.95；与像素差热图和人工检查共同判断，字体抗锯齿可使用明确记录的容差。大面积背景会掩盖文字错误，不能只看全图分数。
- 动态时间、视频画面可以遮罩，但必须记录 mask 位置和理由；不能遮罩真正失败区域来提高成绩。
- Figma 中人工修改标题、调整按钮尺寸、替换图片的操作必须成功，作为实际可编辑性证据。

### 3.3 原型

至少一条“列表→详情→打开弹窗→关闭弹窗→返回”的人工配置流程；每条连线要确认触发区、目标状态、返回行为。URL 相同的两个状态不能合并。原型涉及套餐限制时记录受限项，只按可实际运行的能力通过。

## 4. 选择模式测试矩阵

| 用例 | 预期 |
|---|---|
| 点击文字内部，再扩大父级 | 边界与候选层级准确，页面不导航 |
| 没有 section 标签的完整卡片区 | 可通过容器候选选中 |
| 矩形切到文字/按钮一半 | 严格裁剪保留边界与完整内部文本 |
| 吸附矩形相交多个元素 | 显示最终范围后再确认，不无限扩大 |
| 选父级又选子级 | 默认去重，没有两份相同文本 |
| 排除悬浮按钮 | 按规则移除，原始布局不重排 |
| 跨滚动后继续选择 | 坐标正确；页面改变时识别失效 |
| 选空白或 0 大小范围 | 显示无法采集原因，不产生损坏包 |
| 页面变换/缩放后框选 | 源和输出几何按同一 CSS 坐标对齐 |
| 选择时取消或切页面 | 工具层清理，恢复正常操作，无全局事件残留 |

## 5. 稳定性与恢复矩阵

| 故障/操作 | 要求 |
|---|---|
| 同包连续导入 20 次，每次新 importId | 每次独立根数量正确，不误覆盖旧结果 |
| 同 importId 重复请求 | 不再创建第二份，回执可重发 |
| 捕获 100 次 | 无崩溃、无失控累积监听器/窗口/任务 |
| 创建到一半主动取消 | 删除本次临时根，旧设计保留，状态 cancelled |
| 插件突然关闭 | 标为 interrupted，下次识别残留，可清理重试 |
| 图层完成后桥接断线 | 重传报告，不能重新创建全部图层 |
| 字体缺失/资源 404 | 继续规则明确，有可定位告警 |
| 文件无编辑权限 | 预检终止，无残留输出 |
| 损坏 ZIP/哈希错误/循环树 | 写入前拒绝，错误可读 |
| 端口占用/配对过期/未知客户端 | 连接不成功不丢包，仍可文件导入 |
| 用户在导入中切 Figma 页面 | 锁定原 pageId 或明确中止，不把后半导到其他页 |
| 应用重启/磁盘写入失败 | 已完成包可重开；未完成包不冒充成功 |
| 单资源或总节点超预算 | 预检提示缩小范围，不无界分配内存 |
| 取消后再次运行 | 不受上一次 abort/监听器影响 |

Figma Undo：验证一次成功导入能作为合理撤销单元，撤销不触及用户之前操作；连续导入之间需要明确 undo 边界。失败清理不依赖“对整个文件触发一次撤销”，避免误撤销用户动作。API 语义见 S12，实际行为必须实测。

## 6. 性能目标

在 M0 记录测试机 CPU、内存、OS、Electron、Figma 版本后才开始计时。首次冷缓存与后续热缓存分开；目标网页加载、登录和 Figma 云端同步不混入纯转换时间。

| 工作负载 | 初始目标 | 测量口径 |
|---|---|---|
| 选择高亮 | p95 ≤50 ms | 20 次以上指针更新，命中到显示 |
| 500 输出节点、5 MiB 内资源 | 捕获+转换 ≤5 s；导入 ≤10 s | 各阶段单独计时，不包含页面初始加载 |
| 2,000 输出节点、20 MiB 内资源 | 捕获+转换 ≤15 s；导入 ≤30 s | 超出时定位瓶颈，不能静默减少内容 |
| 主动取消 | 通常 2 s 内到达检查点 | 大图片解码需设置超时和可中止工作单元 |
| 20 次同等工作后空闲 | 内存无持续单调增长 | 比较稳定基线、缓存上限及资源释放，不按一次 RSS 波动判断 |

每 100–200 个节点创建后让出执行权，具体批量按实测调节。性能不达标时先优化读取、资源去重和批次，不先牺牲文字可编辑性。数字可通过决策记录调整，不能为“通过”事后不留痕改目标。

## 7. 环境与真实站点覆盖

最低组合：Windows 11 x64、Figma 桌面当前已验证版本、应用内置 Chromium。另测一组较旧但仍受支持的 Figma 版本是否可得；不可得就记录没有覆盖。

真实站点作为补充样本：用户自有 demo 至少 1 个，普通静态站点 1 个，登录后应用 1 个。优先用可控测试账号，不用公开网站变化替代稳定 fixtures。内置浏览器无法完成某个 SSO 时记录站点兼容问题，不自动导入外部浏览器 cookie。

## 8. 证据目录与记录格式

每次阶段验收创建 evidence/YYYY-MM-DD/task-id，包含：environment.json、steps.md、source.png、figma.png、import-report.json、可选 diff.png 和运行日志。实际没有的文件不能伪造占位。

steps.md 记录：任务 ID、输入 fixture/URL、应用/插件/协议版本、视口/字体/DPR、操作、预期、实际、结论、已知偏差、复现命令。Figma 导出截图先裁到相同根，不包含画布 UI。

用户数据的证据默认本地保存并脱敏。截图本身可能包含敏感内容，不自动上传。需要共享问题时另导出经过检查的最小重现包。

## 9. 阶段通过门槛

- M0：真实 Figma 可创建文字/图片/简单连线；选区叠层坐标可行；桥接给出成功证据或失败回退结论。
- M1：本地基础页面→文件→Figma 真实闭环，支持项全部通过，字体/资源失败有说明。
- M2：所有选择方式与 fixture 矩阵覆盖；支持项达到编辑与几何目标，降级均透明。
- M3：重复、取消、中断、重开、桥接回退与分发包通过；无开放 P0 缺陷。
- M4：指定原型流程实际可运行，节点映射和交互报告一致。
- M5：用户 demo 验收、可交接文档、安装包版本与证据齐全，所有遗留问题分级。

P0 缺陷包括：误改/误删原设计、泄露会话凭据、错误写入目标文件、正常输入导致崩溃且无恢复、把缺失内容冒充完整成功。

## Windows首版实际开发基线（2026-10-20）

F01–F16按支持/降级/未证实项逐项落表于[发布检查](21-desktop-release-verification.md)，不笼统声称全部原生或全图像素通过。新增本地列表→详情→弹窗→返回、同URL多状态、开放组件/插槽、WebP/GIF、本地会话保护资源、CSS动画暂停/恢复和边界告警。用户选择只用本地验证；没有借本地登录推断全部公网兼容。

实际100次主采集流程记录耗时、进程内存和有界历史，20次导入运行实际插件主逻辑但宿主模拟；ZIP真实Deflate从插件文件UI读入，>256KiB真实图片包经多个HTTP块传输。磁盘写入失败注入、终态回执重试和日志轮转由自动测试覆盖。Windows安装副本使用新数据目录、空cwd、仅Windows系统PATH运行，不依赖Node/npm/开发服务器。真实Figma播放/字体/Undo与系统DPI150%等证据缺口保留待用户；旧已接受范围不重新要求验收。
