# 12 多选、排除与新版工作台验收

更新：2026-10-19。版本 m2.2 / 主包协议 1.0.0。前一批直连及 m2.1 均已获用户整体确认，本批新增功能与布局等待用户最终验收。

## 1. 启动与布局

关闭旧桌面应用，在 `E:\WebToPrototype` 执行 `npm.cmd start`。插件的导入逻辑及主协议未改变，可以沿用现有开发插件；桌面重启后需要重新配对。顶部 **连接 Figma** 展开右侧连接设置，生成/复制配对码后，在目标文件的插件中粘贴连接。保持插件运行。

新版操作顺序：

1. 顶部输入网址，或点击“打开测试页”。
2. 工具栏选择 **选择区块**（原“选择 Section”）、**点选页面元素** 或 **自由框选**。需要正常操作网页时点击“浏览网页”，也可在网页内按 Esc。
3. 右侧 **选择内容** 确认范围与列表，选择输出方式。
4. 底部 **预览转换** 可在未连接 Figma 时使用；**转换并发送到 Figma** 重新采集当前内容并发送整批。
5. **转换结果** 中切换画面、查看源参考与告警、修改画面名称，再“发送当前转换”或“保存转换文件”。后两者作用于整批，不是只发送当前预览的一个画面。

右下操作始终固定。配对、插件路径及诊断按需展开。“使用指引”可重新展开三步说明；不用先读 JSON 或开发路径才能转换。

## 2. 多选与排除

- 先用“选择区块”选中一个区块，再勾选 **连续多选**，继续点其他区块。勾选后保持选择模式，重复点已选根可移除；右侧列表也可移除。取消勾选只停止连续选择，已有内容保留。
- 同时选择父级与子级时只保留父级：选中子级后再选父级会合并；选中父级后点子级不会增加副本。转换时还会按当前 DOM 再检查包含关系。
- **排除子元素**：在已选区块内部点需要去掉的内容，虚线标记并加入“已排除”列表。重复点同一元素或在列表点击“恢复”可还原。整块删除使用已选列表“移除”；不能排除整个选中根或范围外内容。
- 排除只影响导出遍历，不修改网页 CSS/DOM，不重排其余元素；父容器原有背景、尺寸、子元素位置和空位保留。父容器自身背景图不会因排除子元素而被修补。
- 当前矩形为单一范围，启用自由框选会替换区块列表。连续多选针对元素/Section，不支持多个矩形、跨 URL 收集或多页面状态管理。
- “当前视口”忽略区块列表及其排除项，直接采集可见范围。切回“当前选区”可继续使用原列表。

## 3. 两种输出

| 方式 | 结果 |
|---|---|
| 独立画面 | 每个去重后的区块一个 screen/Frame，内部坐标相对自己的根。Figma 导入器按已有规则并排摆放各个根 |
| 合并画面 | 一个外层 Frame 包含所有选中根，按网页原坐标差保留间距与位置；空隙不自动填入未选网页内容，合并根透明 |

原始 DOM 绘制顺序用于整批转换，不提供手动拖拽排序。合并不是重新做 Flex/Auto Layout，也不自动把区块紧密拼接。每次最多 20 个区块、100 项排除；整批最多 10000 图层，单区块沿用 3000 元素/5000 图层等提取预算；图片仍遵守总 30 MiB/64 Mi 像素和 JSON 50 MiB 限制，不因多选扩大预算。

## 4. 源预览与文件

“源网页参考”展示转换前截图，**仍会看到已排除的内容**，合并截图也可能看到空隙内未选内容。它只供源图对照，不是转换图层的渲染图；实际是否排除请检查 Figma 与包内原生节点。画面出视口时可没有截图或仅部分截图，转换仍会处理已加载区块，不自动滚动拼接。

结果页有画面下拉框，各画面独立命名，修改名称不会把另一画面一起改名。单击“保存转换文件”保存整批主 JSON 及可用的源附件：

```text
batch.json
batch.json.preview.png
batch.json.preview.json
batch.json.screen-2.preview.png
batch.json.screen-2.preview.json
```

第一画面保留原附件命名以兼容旧包，后续附件带 screen ID。重开时逐个核对包版本、screen ID、尺寸与摘要；缺失/错配只影响对应源预览，不影响主包导入。Figma 只需主 JSON，直连会在一个任务内发送整批 screens。命名变更递增 revision，因此再次发送属于新版本，可能创建新副本；未改名/未重新采集的同会话缓存发送继续受去重保护。

## 5. 用户验收

| 编号 | 操作 | 预期 |
|---|---|---|
| C01 首次使用布局 | 重启；用“使用指引”、两个页签和连接入口，缩小到约 1000×650 | 工具、区块列表、结果和连接各有明确入口；底部主操作可见，不用查开发 JSON 才能完成 |
| C02 连续多选 | 测试页选择“订单列表”，开启连续多选并选“选择行为验证”；测试移除/重复点选/清空/停止多选 | 列表与轮廓一致；停止多选保留内容；同一块不会重复 |
| C03 父子与排除 | 多选后点“选中父级”，或用元素工具选择已选容器内部；再排除订单行中的一段文字并转换 | 父子不重复；被排除节点不在 Figma 中，其余内容保持原位置；列表恢复后可重新转换回来 |
| C04 独立/合并 | 两个区块分别选择两种输出并发送 | 独立为两个根 Frame；合并为一个根且保留区块相对位置，空隙里不增加未选内容；文本/图形可编辑 |
| C05 结果和重开 | 切换结果画面，给第二个画面改名后直接点保存，再重开 | 整批画面保留，改名只作用于第二个；每个可见画面的源参考能切换；缺附件只提示 |
| C06 整批直连回归 | 配对后连续发送；同缓存再点发送；正常浏览、视口、矩形也各做一次 | 一个批次在同一目标页自动导入；未改版本的缓存不重复创建；原采集方式仍可用 |

回报：`C04：通过/失败；选择范围；输出方式；桌面状态；Figma 中根数量与异常；截图/JSON/导入报告路径`。所有最终 Figma 与首次使用体验由用户回报，不把开发自检代替验收。

## 6. 开发验证范围

运行 `npm.cmd run check`；实际 Electron 功能命令新增 `npm.cmd run smoke:multiselect`。它检查去重、排除、几何、整批资源、命名/附件/重开、失效恢复、工作台对比度、键盘及两种窗口尺寸。原 `smoke:capture`、`smoke:selection`、`smoke:bridge` 继续回归；桥接脚本增加整批多画面传输，用真实 UI/HTTP 与模拟画布宿主，不写真实 Figma。

证据与最终测试结果在 [PROGRESS](PROGRESS.md)。本批不包含有界全页、自动交互、安装包和 Android。
