# 11 本地直连与一键发送验收

更新：2026-10-19（Australia/Sydney）。批次：M3 本地桥接首版。实现完成，真实 Figma 最终验收由用户执行；不改变已获确认的 m2.1 结果。

## 1. 启动新版

1. 关闭自己原来运行的 WebToPrototype 窗口，在 `E:\WebToPrototype` 执行 `npm.cmd start`。只需保留一个生产实例，端口固定为 43821。
2. 在 Figma 桌面打开一个可编辑的 Design 测试文件，切到希望接收结果的页面。
3. 关闭旧插件窗口，重新运行 Development 菜单里的 **WebToPrototype · M0 验证**。旧名称保留以复用现有开发插件。应看到新增的“连接桌面应用”区域。
4. 若插件仍是旧界面，从 `E:\WebToPrototype\apps\figma-plugin\dist\manifest.json` 重新加载开发插件。不要选择 src 内的文件。当前使用 devAllowedDomains 中的 localhost 开发权限，不是已发布插件。

无需重新安装 npm 依赖。没有安装包，也不需要 Figma REST token、OAuth 或付费转换服务。

## 2. 日常发送流程

1. 桌面右侧“发送到 Figma”点击 **生成配对码**，再点击 **复制配对码**。
2. 粘贴到 Figma 插件的“本机配对码”，点击 **连接桌面应用**。配对码 5 分钟有效、只能使用一次。
3. 检查桌面显示“已连接”，并核对接收文件/页面名称。插件在该文件内保持运行；关闭插件后不能后台接收。
4. 在桌面打开目标网页。如果采集 Section/元素/矩形，先选择范围；在“一键采集范围”选择 **当前选区**。如采集可见网页，选择 **当前视口**。
5. 点击 **转换并发送到 Figma**。本次重新采集网页并发送，插件自动创建原生可编辑图层，桌面显示进度及最终告警数。无需保存或手工选择 JSON。
6. 继续选择另一处范围并再次点击，即可连续采集。当前一次只运行一个导入任务。

已经转换过、修改名称或重开的包，可点击下方 **发送当前转换**。它发送当前缓存，不重新读取网页；如网页已变动，使用上方“转换并发送”。命名后发送会递增该包 revision。源预览仍是独立附件，不会作为整张截图替代可编辑图层。

## 3. 验收清单

| 编号 | 操作 | 预期 |
|---|---|---|
| B01 配对 | 按第 2 节操作；核对文件和页面 | 两端显示连接目标；重复使用旧配对码失败；重新生成会断开旧连接 |
| B02 连续发送 | 发送当前视口，再选择订单 Section 发送 | Figma 出现两份对应的新 Frame；不弹文件选择器；中文/英文可编辑、图片和底边框与原流程一致 |
| B03 缓存防重复 | B02 成功后，不重新转换，点击“发送当前转换”两次 | 返回同一个任务结果，当前配对会话不会因此再次生成同包同 revision 的图层；重新采集则有新包，可创建新副本 |
| B04 页面保护 | 在同文件切到另一 Page，等待约 1–3 秒；随后切回 | 原配对保持绑定，发送按钮禁用；切回恢复。要更换接收 Page，应在该页重新生成/粘贴配对码 |
| B05 断连与回退 | 关闭插件，等待约 8–10 秒；再重开并重新配对 | 桌面显示连接中断；保存 JSON 与手工文件导入仍可用；旧导入中任务不会因重开而自动再创建 |
| B06 报告与失败处理 | 成功后点“保存导入报告”；可另测插件“取消导入” | 报告的 packageId/importId、targetPageId、根 ID 和 counts 对应实际图层；取消/失败显示明确结果，不删用户已有内容 |

建议先用内置订单页跑 B01–B04，再在自己的 demo 上做一次。若内容较少，导入很快，进度可能直接跳到完成。各项只记录实际操作结果，不要求为了看到进度而造超大页面。

回报格式：`B02：通过/失败；操作；错误原文；桌面状态；Figma 当前文件/页面；是否新增图层；截图或报告路径`。不需分享配对码或令牌。

## 4. 断线、重试和幂等边界

- 正常短暂网络失败时插件只重传回执；已经创建的图层不因此重新导入。回执尚未确认前插件不会领取新任务。
- 约 8 秒无心跳标记失联：未领取任务取消，已领取任务标记 interrupted。同一插件会话恢复后可补交原回执，但不会自动重建不确定任务。
- 看到 interrupted 时先检查 Figma 当前结果与“读取上次报告”；如有本插件未完成临时根，可用“清理本插件残留”。不要因状态不确定就反复重新采集。确认旧结果后，再决定保留、手动删除或重新采集。
- 桌面或插件重启后需重新配对。新插件运行实例有新的 bindingId；同包同版本的不确定任务会阻止自动重建。已成功的旧包在新的配对实例仍可作为新副本导入；本功能不是跨文件全局去重或覆盖更新。
- 当前任务日志最多保留 20 项，桌面展示最近 10 项；插件保留最近 3 个成功直连回执。保护范围有限，不保证无限期的全局 exactly-once。手工文件导入仍按新副本运行。
- 当前插件“取消导入”只取消正在执行的导入，不等同取消尚未领取的任务。桌面“断开”会停止旧连接，保守标记未确认任务。
- 主 JSON、图片、图层映射会通过本机回环连接传输。配对码和 token 只在会话内存，日志不保存；成功报告会留在本地任务日志。源网页拿不到桌面 IPC 或连接 token。

## 5. 排查

| 情况 | 处理 |
|---|---|
| 看不到连接区域 | 重启桌面、关闭并重开更新后的开发插件；必要时重新载入 dist/manifest.json |
| 配对码过期或错误 | 在桌面重新生成并复制；连续错误 5 次后等待约 1 分钟 |
| 本机服务不可达 | 确认桌面正在运行；用插件“检测本机连接”。生产固定 http://localhost:43821；端口被占用会启动失败，先退出自己旧的应用实例 |
| 提示页面不同 | 切回配对页，或在目标页重新配对；不自动改变接收目标 |
| E_BRIDGE_JOURNAL_INVALID | 本地任务日志损坏，直连保守停用；保存原日志与错误交给开发排查，仍可使用文件导入，不直接删除记录以强行重试 |
| 源截图有画面但不能自动接收 | 截图预览和 bridge 是独立步骤，先检查连接/任务状态；已转换结果可保存 JSON 回退 |

不修改 Figma 或浏览器安全设置来绕过网络限制。当前验证版不支持自选桥接端口、资源分块、关闭插件后的自动唤醒、多文件并发或 Android。

## 6. 开发证据范围

`npm.cmd run check`：37 项测试、两套 TypeScript 检查及构建通过。包含真实 Node HTTP 鉴权/CORS、日志/重启/回执测试，以及真实插件主代码的模拟 Figma API 故障注入；模拟节点不是真实 Figma 导入证据。

`npm.cmd run smoke:bridge`：实际 Electron、真实网页采集、真实插件 UI（opaque sandbox iframe）和真实回环服务运行；画布宿主由脚本模拟，报告外层明确 `figmaTested:false`。验证连续发送、图片完整性、页面保护、断开、一次性码及丢失响应后的回执重传。模拟宿主为验证 wire contract 返回报告形状，不作为 actual_import 的真实画布证明。
