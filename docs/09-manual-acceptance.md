# 手工测试与验收（本轮）

日期：2026-10-19。测试负责人：用户；实现与构建检查：Codex。请将结果写入 [USER-TEST-RESULTS.md](USER-TEST-RESULTS.md)，或按末尾模板直接发回聊天。

本文件保留上一批 Section/资源校验操作。原流程与 BUG-001 已获用户确认；m2.1 的视口、矩形和源预览请按 [10 新功能验收](10-viewport-and-rectangle-acceptance.md)，不要把下文历史范围描述当作当前版本缺少矩形能力。

本轮交付两项：资源字节校验，以及真实网页单个元素/Section → 自包含 JSON → Figma 可编辑图层。稳定性项目由用户手工执行，未提前标记通过。Android、矩形框选、多选、全页、Auto Layout 和真实网页自动交互连线不属于本轮交付。

## 1. 启动与更新插件

1. 在 PowerShell 执行：

   ```powershell
   Set-Location -LiteralPath 'E:\WebToPrototype'
   npm.cmd start
   ```

   本机已安装依赖，无需重新安装。`start` 会先构建，再启动桌面应用。请先关闭旧版 WebToPrototype；端口 43821 被占用会导致启动失败。暂未提供 exe 安装包。

2. 打开 Figma 桌面版中的可编辑 Design 测试文件，建议新建一个空白 Page。
3. 若旧插件面板还开着，先关闭。运行开发插件 **WebToPrototype · M0 验证**。保留此名称和原有插件 ID 是为了兼容已经安装的开发插件，面板内已增加真实包导入。
4. 如果面板没有“导入桌面端保存的真实网页转换包”的说明，重新从 Main menu → Plugins → Development → Import plugin from manifest 导入：

   `E:\WebToPrototype\apps\figma-plugin\dist\manifest.json`

5. 不需要 Figma token，也无需运行“检测本机连接”。本轮文件链路不使用实时桥接。

## 2. 先验收真实网页转换（最重要，约 10 分钟）

### T01：选择并转换订单 Section

1. 桌面应用点击“打开测试页”。这是普通 HTML 页面，转换器读取其当前真实 DOM，不调用人工协议样例。
2. 点击“选择 Section”，然后在网页的“订单列表”标题上单击。右侧展开“选区与布局诊断”时应看到 `id: orders`。
3. 也可以用“点选页面元素”选中标题，再点击“选中父级”选中订单区块。“选择 Section”优先找最近的 section/article/main/role=region；没有语义容器时，可用点选加父级切换选择普通 div。
4. 点击“转换选中区块”。右侧应出现图层、文本、图片与告警数量。
5. 修复单边边框后，固定窗口宽度下预计为 **21 图层、7 个文本、1 张图片**（新增两条可编辑底部分隔线），区块约 **688 × 386.14 CSS px**。窗口大小、字体、换行不同会改变结果，不以该数字作为所有环境的硬性要求。
6. 两条订单行各只有底部分隔线，不应出现行的上边框和左右边框；外层 Section 的完整圆角边框应保留。普通实线底边框不再产生“统一边框近似”告警。

通过标准：只导出订单区块；正文和按钮文字各出现一次；中英文完整；小棋盘图片存在；没有整块页面截图替代文字。

### T02：保存、重开和来源信息

1. 将“画面名称”改为“订单区块验收”，点击“保存 Figma 文件”，保存为自己方便找到的 `orders.capture.json`。
2. 点击“重开转换包”，选该文件。应恢复名称、图层数量与告警。关闭应用再启动后，也可重开该文件。
3. 可用文本编辑器查看 JSON：`artifactKind` 应为 `capture`；`assets` 中包含图片字节和 SHA-256；`source.url` 不保留 query、fragment 或 URL 登录凭据。
4. 本地自动记录 `last-capture.json` 的目录可在“开发诊断 → 本地记录目录”查看。该缓存仅保留最近一次转换；正式留存请主动保存文件。

通过标准：保存与重开内容一致；文件自包含。改画面名会递增 revision。

### T03：导入 Figma 并确认可编辑

1. 插件中不勾选“允许导入人工样例”，在“导入自包含 JSON”选择刚保存的真实网页文件。
2. 等待出现“导入完成”。插件会在当前 Page 追加 Frame，并选中、缩放到结果。
3. 双击“订单列表”，改成“本周订单”；双击中英文段落，修改一个英文单词。
4. 在图层面板选中按钮容器，修改填充色或圆角，再修改按钮里的“打开详情”文本。
5. 选中图片子图层，确认它是有 IMAGE 填充的可编辑图层，可移动、调整尺寸或替换填充。图片本身保留位图，不会被重绘为矢量。
6. 对照桌面源页面，检查区块尺寸、文字位置、基础颜色、圆角、图片和层级；字体替代可能导致视觉偏移，应在报告中出现。
7. 点击“下载报告”。报告应为 `reportKind=actual_import`、`inputKind=capture`，packageId 与导出 JSON 一致，counts 与实际图层一致。转换告警应保留，字体替代则额外列出。

通过标准：文字、按钮容器、图片可分别编辑，内容不缺失、不重复；基础区块尺寸在 Figma 面板中与 JSON 一致（正常取整误差可在 1px 内）；现有无关图层未修改。`succeeded_with_warnings` 需要逐条看告警，不代表导入失败。

本轮真实网页导入 **没有自动交互连线**，按钮不会自动打开原网页对话框。验证网页行为转换要等 M4，不能据此判定本轮导入失败。

2026-10-19 边框修复复验：关闭旧桌面应用，重新 `npm.cmd start`，重新采集、导出并在 Figma 导入新包。旧 JSON 已固化错误的整圈边框，单纯重导入旧文件不会修正。本次沿用已有 SHAPE 图层协议，无需重新安装插件。检查两条订单行各只有一条底线；图层中可分别选中“边框 / bottom”。

### T04：自己的 demo 与独立性

1. 保持自己的 demo 服务运行，在桌面地址栏输入 `https://...` 或 `http://localhost:端口` / `http://127.0.0.1:端口`。
2. 先选一个简单卡片或 Section，不要直接选整个复杂应用。重复 T01–T03。
3. 保存包后关闭源 demo 服务，再导入 Figma。已固化的 PNG/JPEG 仍应显示，说明导入不依赖源站在线。
4. 记录 URL 的域名/路径、所选区块、预期与实际；不要把登录 token 或 Cookie 发回聊天。

此批历史兼容范围：普通 DOM 文本（按渲染行拆分）、容器、纯色背景、基础边框/圆角、基础外阴影、PNG/JPEG。彼时图片使用居中铺满，object-fit、背景平铺与裁切可能不同；WebP/GIF/SVG暂不固化。图片失败保留占位框并告警；整个资源预算超限则拒绝捕获，不静默截断。后续图片/渐变已在m2.4扩展，当前m2.7原生SVG范围见[docs/17](17-svg-and-icons-acceptance.md)，不要把历史限制当作当前能力。

复杂 transform、层叠、filter、渐变、伪元素、SVG、iframe、canvas、video、表单状态和 Shadow DOM 尚未完整重建。开放 ShadowRoot 可发现时会提示；闭合 ShadowRoot 无法可靠遍历。不要把这些情况描述为已经支持。

## 3. 资源校验验收（约 5 分钟）

构建已生成 [examples/acceptance](../examples/acceptance) 中 9 个 **人工**测试文件。在插件展开“人工样例与开发验证”，勾选“允许导入人工样例”，再通过文件输入逐个选取。下列无效文件必须在创建图层前拒绝，不应让已有图层消失。

| ID | 文件 | 预期 |
|---|---|---|
| R01 | 01-native-Chinese-English.json | 正常导入；中文/English 可编辑；包含一张 PNG 和两条往返连线 |
| R02 | 02-invalid-sha256.json | 拒绝，提示 SHA-256 mismatch，无新增图层 |
| R03 | 03-invalid-mime.json | 拒绝，提示 MIME mismatch，无新增图层 |
| R04 | 04-invalid-dimensions.json | 拒绝，提示 dimensions mismatch，无新增图层 |
| R05 | 05-over-dimension-limit.json | 拒绝，宽度超过 4096，可能显示 Schema 的 maximum 错误 |
| R06 | 08-over-pixel-budget.json | 拒绝，提示 total image pixels，无新增图层 |
| R07 | 09-corrupt-png.json | 拒绝，PNG 校验失败；摘要虽匹配，损坏数据仍不能导入 |

当前限制为项目自己的首版预算，不是 Figma 官方上限：单图 ≤10 MiB，单边 ≤4096px；资源总字节 ≤30 MiB；累计图片像素 ≤64 × 1024 × 1024；JSON 文件 ≤50 MiB；整个包 ≤10000 节点、≤200000 UTF-16 文本单位。单次网页采集更保守：≤3000 元素、≤5000 节点、≤60000 文本单位、≤200 个图片请求；超限应提示缩小区块。

两端验证 SHA-256、实际字节长度、MIME、图片头尺寸及预算；PNG 额外检查块边界与 CRC。桌面使用 Chromium 解码，插件在创建图层前使用 Figma 图片解码再核对尺寸。JPEG 的共享检查不是完整解码器，最终解码仍由宿主执行。文件资源路径/ZIP 在当前版本明确拒绝。

## 4. 稳定性测试（用户执行，约 10–20 分钟）

| ID | 操作 | 通过标准 |
|---|---|---|
| S01 | 进入元素/Section 选择，按 Esc；随后正常单击“打开详情” | 高亮退出；网页按钮恢复正常，出现对话框；选择期间单击只选择，不触发对话框 |
| S02 | 选中区块后滚动，再选择父级；改变应用窗口宽度后重新采集 | 高亮跟随当前区块；重采集尺寸与此时页面一致，不复用旧尺寸 |
| S03 | 选中区块后打开另一个 URL 或页内锚点，再点转换 | 旧选择失效，要求重新选择或正常重新采集，不导出前页节点 |
| S04 | 使用页面自身缩放/开发工具修改缩放后重新采集（若方便） | CSS px 和缩放元信息一致；如没有方便的缩放入口可记录“未测”，当前应用未做缩放控制 |
| S05 | 导入 06-missing-font.json | 导入完成并明确提示字体替代，文字仍可编辑；不可无声替换 |
| S06 | 导入 07-cancel-2000-nodes.json，进度出现后立即点“取消导入” | 提示 E_CANCELLED；本次临时根与本次输出被清除，已有图层保留；之后可再正常导入 |
| S07 | 成功导入 R01 后，点 Figma 画布空白处取得焦点，再按 Ctrl+Z | 本次导入作为可理解的 Undo 边界撤销，已有无关图层保留；记录实际撤销次数 |
| S08 | 导入大样例途中直接关闭插件，再重开 | 如存在本插件 staging 根，正常导入应阻止并提示清理；点“清理本插件残留”后可重试；已成功 committed 根和用户节点不被清除。若宿主自动回滚、没有残留，记录实际表现 |
| S09 | 同一个正常包导入两次 | 当前设计生成两个独立副本；不是幂等更新，不应覆盖第一次的手工修改 |
| S10 | 真实包另存后退出桌面应用，再在 Figma 导入；重启桌面重开该包 | 图片和文字仍可导入；文件链路无需桌面后台在线 |

S06/S08 为故障测试，建议在专用测试 Page 上操作。不要清理自己不认识的图层；清理按钮只针对带本插件 owner 与 staging 标记的根。

如果任何取消/中断测试删除了无关图层、无法清除自己的临时根，或普通包创建到一半失败，请优先回报，后续先修复此问题。
